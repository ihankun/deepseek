# Agent Note: Electron desktop shell over the web profile

Status: implemented

English | [中文](2026-08-14-electron-desktop-shell.zh.md)

## Problem

The browser UI runs only as `dsh web`: a local server the user opens in a browser tab. A desktop surface is missing — a windowed shell with a tray icon that hosts the same web app without a browser, started with one command from the checkout.

## Decision

**A new profile stacks a desktop bundle over the web layer.** The shipped `electron` profile template is `@deepseek-ai/dsh-base`, `@deepseek-ai/dsh-web-app`, `@deepseek-ai/dsh-electron-app`, and `dsh electron` is a hardcoded alias for `--profile electron`, mirroring `dsh web`. The web composition — webserver, web runtime, `/api` gateway, browser roster — is reused unchanged; nothing in `dsh-web-app` or the web bundle patches for the new surface.

**The desktop bundle is one package hosting two entries.** `apps/electron` (`@deepseek-ai/dsh-electron-app`) ships the host plugin (`lib/index.js`) and the Electron main process (`lib/main.js`, resolved through the package's `./main` export). The patch layer inserts one row, `electron-app`, that injects the `webServer` service and needs no config.

**The host plugin launches Electron against the bound server.** It computes `http://host:port` from the active web server, spawns the Electron binary with that URL in `DSH_WEB_URL`, and couples the two lifetimes: the shell's exit requests tree shutdown through `ctx.appExit`, tree teardown kills the shell, and the piped stdin's EOF exits the shell when the launcher dies without a signal. A missing `appExit` fails loud at mount.

**The main process waits for the server, then owns the window and tray.** It probes the URL until it answers (30s budget), creates the window and shows the tray. The tray icon is the black-shape `deepseek-tray` asset resized to the 24pt menu-bar size (48px @2x) and marked as a template image, so macOS renders it in the menu bar's light/dark color; the window/dock icon is the single `icon.png`, matched to the DeepSeek desktop client icon (a dark-gray rounded rect inset 9% per side with the white logo, following the release-page icon.icns colors and the Apple icon-template proportion; the reference file corner is 6.1% because the system overlays the standard mask on installed apps), generated by `gen:icons` via sharp. Closing the window quits the app on every platform (single-window shell), and quitting reports the exit back to the launcher. A second instance focuses the existing window.

**A packaged app runs its own server.** `electron-builder` packages the desktop bundle with the full `@deepseek-ai/dsh` dependency tree; `electron:build:mac` / `electron:build:win` are root scripts for the mac/win targets. A packaged app (no `DSH_WEB_URL`) starts an `ELECTRON_RUN_AS_NODE` child running the bundled CLI (`node_modules/@deepseek-ai/dsh/lib/bin.js web --port 0`), parses the readiness line for the OS-assigned URL, and mirrors the child's lifetime (quit kills it, its exit quits the app). The mac `.icns` and win `.ico` are generated from the 512px manifest png by electron-builder; `npmRebuild: false` keeps the N-API modules built for Node, and `smartUnpack` handles native `.node` files. Failures before the window opens show an error dialog instead of a silent exit.

## Alternatives considered

**A `dsh electron` subcommand spawning a separate `dsh web` child.** Rejected because the profile composition is the shared surface contract: one tree, one server, one shutdown path. Two processes would need port discovery, health handshakes, and a second lifecycle path for no capability.

**Loading the built `dist/index.html` as a file URL.** Rejected because the web app requires the host tree (window.__DSH_BOOT__ injection, `/api` gateway), so the server is not optional.

## Consequences

`pnpm run electron:dev` (a root script forwarding to `pnpm dsh electron`) boots the web profile plus the shell. The tray icon is the existing `deepseek-tray` asset; the window and dock use the existing web-app-manifest-512 icon. Electron is a runtime dependency of the desktop bundle, so profile installs carry the binary. The shell has no dev-tools shortcut and no auto-hide behavior beyond the OS; those remain follow-ups. Packaging relies on electron-builder's pnpm-workspace dependency collection, which is verified by building each target; the packaged app reads the machine's dsh environment (key, `.env`, home) rather than bundling credentials.
